# Revit Model MCP 文档站整改实施规格

状态：Ready for agent · 2026-10-30
目标站点：http://192.168.100.120:8099
交付范围：生成器、文档内容、导航与搜索、构建校验、静态 HTTP 服务、发布链路。本文是实施规格，本轮只编写并发布规格。

## Problem Statement

读者从搜索或深链接进入工具页时，难以判断页面描述的是已发布版本还是集成分支。同名 tool 的参数存在版本差异，页面却只显示“当前版本已有”。英文搜索混入中文结果，移动端参数说明难读，首页的编辑入口指向错误来源。

维护者看到构建与链接检查通过，仍可能发布缺失描述元数据、语言标记错误或来源不明确的站点。自动发布遇到脏工作树长期跳过，状态却表现为成功，发布目录切换还存在短暂空窗。

审计快照包含 35 个已发布 tool、80 个分支 tool、27 个同名 tool，其中 19 个参数名集合不同；这些数字仅作基线，不作为未来固定数量约束。

## Solution

每个工具页明确标注版本、发布状态和契约来源；同名工具页相互链接并提示差异。搜索优先当前语言和精确 tool 名，缺译页面诚实显示语言覆盖情况。保留现有站点技术栈与生成器，用生成结果、HTTP 响应和浏览器操作组成发布验收门禁。

发布只消费明确的干净源码版本，记录构建来源，校验成功后切换到新产物，失败继续服务上一份。采用九个可独立验收的工作包，先修版本识别和服务正确性，再完善内容与体验，最后收口上线验收。

## User Stories

1. As a 发布版用户, I want 在深链接页看见适用版本, so that 我能选对契约。
2. As a 集成分支用户, I want 看见未发布状态和来源版本, so that 我了解功能成熟度。
3. As a 工具使用者, I want 按稳定的 tool 名识别页面, so that 显示标题变化不影响定位。
4. As a 工具使用者, I want 在同名工具页之间切换, so that 我能对比两个版本。
5. As a 发布版用户, I want 看见参数差异提示, so that 我不会把分支参数用于发布版。
6. As a 新读者, I want 从目录选择发布版或分支, so that 我知道应从哪里开始。
7. As an 英文读者, I want 默认搜索英文内容, so that 结果易于理解。
8. As a 搜索用户, I want 精确 tool 名优先返回工具页, so that 我无需先浏览首页。
9. As a 搜索用户, I want 看见结果的版本与语言, so that 我能识别同名结果。
10. As a 搜索用户, I want 无结果时获得可操作提示, so that 我能改词或切换语言。
11. As a 单语页读者, I want 知道另一个译本尚未提供, so that 语言切换不会通向假译本。
12. As a 分享者, I want 分享卡片显示对应语言的摘要, so that 收件人理解链接内容。
13. As a 搜索引擎使用者, I want 访问统一页面地址, so that 相对链接和语言入口正确。
14. As a 手机读者, I want 清楚阅读参数说明, so that 我无需反复横向拖动。
15. As a 键盘用户, I want 首页与错误页也能跳到正文, so that 导航不会挡住阅读。
16. As a 深层页读者, I want 返回分组和访问相邻工具, so that 浏览路径连续。
17. As a 文档贡献者, I want 编辑入口指向真实维护源, so that 我的修改能进入生成结果。
18. As a 迁移用户, I want 每个 fork tool 有有效链接或明确移植状态, so that 我知道下一步。
19. As a 无人值守实例操作者, I want 了解对话框自动应答的作用域与启用时机, so that 我能配置适合该实例的运行方式。
20. As a 性能数据读者, I want 区分历史观察和可复现实验, so that 我能合理使用数字。
21. As a 文档维护者, I want 保留空字符串、null 和无默认值的区别, so that 参数表忠于契约。
22. As a 翻译维护者, I want 原文变化时收到过期提示, so that 旧译文不会静默发布。
23. As an HTTP 客户端使用者, I want GET、HEAD 和缓存协商遵循同一表示规则, so that 缓存行为可靠。
24. As a 访问者, I want 错误 URL 返回受控状态和有效入口, so that 服务持续可用。
25. As a 运维人员, I want 区分发布成功、跳过、失败和最近成功版本, so that 状态可观测。
26. As a 运维人员, I want 发布失败时保留上一份站点, so that 更新不会中断阅读。
27. As a 运维人员, I want 查询产物来源和回退版本, so that 我能复现与恢复发布。
28. As a 开发者, I want 在隔离测试站点验证整改, so that 测试不会覆盖在线站点。
29. As a 项目维护者, I want 按页面所有权决定翻译范围, so that 上游更新不会制造无主翻译债。
30. As a 验收者, I want 每项 review 有修复、校准或延期结论, so that 规格收口可核对。

## Implementation Decisions

### D1. 版本、契约与语言覆盖

- 保留发布版与集成分支两个目录，不合并其 inputSchema，不修改产品 tool 契约。以 tool 名作为关联键。
- 每份目录数据声明版本标识、release/integration 状态、完整来源 SHA 和页面语言覆盖；页面所有权区分 fork 与 inherited。发布版本号从现有发布元数据读取。
- “发布版存在同名 tool”与“本页契约可用于发布版”分别表达。分支页统一显示未发布横幅；重复页双向链接，参数不同则显示契约差异提示。比较完整 inputSchema 的结构语义，包括参数、required、类型、默认值和约束，不只比较名称。
- 页面标题使用显示名、tool 名、版本/状态；同一语言内保证页面身份可区分。跨语言同名标题本身不判错。
- 遵循 ADR-0007：fork 自有内容维护声明过的译本；inherited 内容可保留英文单语。构建按显式语言覆盖校验，缺失声明为必需的译本仍报错。只为实际存在的译本生成语言切换与 hreflang，不恢复全站强制双语承诺。
- 与上游整合规格 #27 协同：本规格适配目录与站点，不执行产品 rebase，也不改两条产品线的 write gate 或 policy。

### D2. 元数据、搜索与导航

- 生成页从内容源生成同语言 description；手写页使用明确摘要或同语言站点 fallback。输出 description、OG/Twitter 摘要及与页面语言一致的 locale。
- canonical、og:url、hreflang 使用当前构建配置的绝对 URL，兼容 LAN 根路径和 GitHub Pages 子路径。hreflang 仅连接实际译本且双向对应。
- 保留现有搜索机制，给索引和结果补充语言、tool 名、目录状态。默认过滤当前语言；提供显式“所有语言”入口。精确 tool 名的前两条结果应为适用工具页；发布版先于分支版，首页不得压过精确工具页。
- 搜索建议作为后续体验项；本次必须有明确的无结果说明和切换语言入口。先验证缓存和传输体积，再决定物理拆分索引，不强制重写搜索引擎。
- 目录提供双向版本选择；移植表每行链接到现有工具页或明确的移植状态锚点；分组有可链接落点。把视图、图纸、明细表拆为有语义的分组，保持现有深链接可用。
- 编辑入口指向真正维护源；自动生成页指向生成器或内容源说明，不引导读者手改生成文件。

### D3. 内容真实性

- 补充 `REVIT_MCP_ANSWER_DIALOGS=1` 的说明：在目标 Revit 实例启动前设置，由 add-in 启动时读取；显式开启后对该实例所有对话框尝试自动应答，默认保持原行为。说明作用域、适用场景、退出方式及版本适用性，不把它作为普通交互会话默认值。
- 修复性能页错误的“全文在另一语言页”引用；有可定位日志就链接来源、版本、环境与方法，缺原始记录则标为历史观察和不可复现摘要。任何新性能保证需要新实验回执，禁止补造记录。
- 参数表区分空字符串、null、缺省值；年份与环境变量必填属性对照适用版本核实；路线图用带日期和来源的状态，未证状态明确标示。
- 中文 UI 名称和模型示例值可保留为字面值，旁附解释；它们不等于漏译。对 prose 统一领域术语；原文指纹校验扩展到实际维护的 capability 译文。

### D4. HTTP 与静态资源

- 有效目录的无尾斜杠地址和显式 index 地址 301 到规范目录地址，保留 query；真实缺失路径维持 404，避免循环跳转。
- GET/HEAD 在相同请求头下选择相同表示；HEAD 无正文，Content-Length 如存在须描述对应 GET。按编码区分强 ETag 或使用合法弱 ETag，正确处理 gzip 的 q 值及 identity。
- 可协商压缩的响应及其 304 保持一致 Vary；If-None-Match 优先于 If-Modified-Since。304 保留应有验证器和缓存头，不要求发送正文。
- gzip sitemap 固定为 gzip 文件下载语义：`application/gzip`、无额外 Content-Encoding，解压一次得到 XML；普通 sitemap 保持 XML，不二次压缩 gzip 文件。
- 未指纹化资源要求重新验证；只有确有内容哈希的不可变资源使用长期缓存。
- 无效编码、NUL、路径越界和资源不存在返回受控 400/404；处理后服务继续响应。根错误页提供两种语言入口，英文路径错误页优先英文入口。
- 提供根 favicon 别名及按部署目标生成的 robots。LAN 配置默认不索引，公开站点指向本源 sitemap；robots 不作为访问控制。普通缺失资源返回轻量错误，文档导航保留人类可读错误页。manifest/security.txt 不为消除 404 而凭空创建。
- 无引用 GIF 从发布包排除即可；删除源文件前检查 Markdown、HTML、CSS、JS、srcset 与社交元数据引用。不能把未加载到首页的资源计成首页下载负担。

### D5. 发布与可追溯性

- 自动发布使用独立的干净 checkout/worktree 固定到目标 commit，不依赖开发工作树是否干净，不自动提交、stash、丢弃或推送用户改动。
- 来源不干净、同步失败、生成检查失败、构建失败均保留当前站点，返回可区分的非成功状态；同版本无变化可以成功 no-op，日志须明确。记录最近尝试、最近成功、原因及产物标识。
- 生成公开构建清单，包含 source SHA、目录快照 SHA、构建配置摘要、工具版本、UTC 时间、产物标识和校验结论，不含凭据与本机敏感路径。
- 使用不可变发布目录和原子 current 指针切换，至少保留当前版和上一版。HTTP 服务每次请求解析一次发布根，整个请求使用该快照；启动时固定解析符号链接的行为需要一并调整。旧目录清理不得影响在途请求。
- 迁移现有实体发布目录时保留原服务根，先用独立目录和端口验收再切换；切换后健康检查失败应恢复上一指针。验收证明的是请求期间无路径空窗，不声称多请求浏览器会话绝对跨版本一致。
- 在线版本与构建清单及部署目标一致即可，不要求等于开发工作树当前 HEAD。回滚到历史版本是有效部署。

### D6. 可达性与阅读

- 首页、英文首页、错误页都有可聚焦且有效的跳转正文链接。
- 窄屏参数表保留表头语义、参数/说明关联和所有字段；将辅助字段折叠到可访问详情或垂直排布。390px 下主要参数说明无需横向滚动；确需横滚的数据表保留键盘入口和可发现提示。
- 保留既有 AA 对比度、焦点、抽屉 inert、命名复制按钮、减少动画、打印与图片尺寸优化。修复不以隐藏字段或降低字号换取视觉通过。

## Testing Decisions

- 主验收边界是“源码输入 → 生成/构建 → HTTP 服务 → 用户可观察结果”。复用现有生成器 unittest、站点审计器和浏览器验证；只对缓存与发布故障增加必要的外部接口测试，不测试私有函数调用顺序或模板排版细节。
- 静态检查扫描全部声明页面，排除模板副本和非页面资产。验证契约来源、版本横幅、互链、元数据、规范地址、实际语言覆盖及导航，不硬编码 288 页或 35/80 个 tool。
- 基于现有“错误语言切换”“缺失语言 sibling”“过期契约指纹”“快照来源”“生成确定性”测试扩展：显式单语 inherited 页通过，缺失承诺译本失败；同名异参且无提示失败；required/type/default 改动可被发现。
- LAN 根路径和公开子路径各做严格构建。相同输入的页面与资源应确定；构建时间、产物 ID 等清单字段按定义归一后比较。
- 启动临时目录和临时端口的真实 HTTP 服务，用相同 Accept-Encoding 比较 GET/HEAD，覆盖 200、301、304、404、gzip q=0、编码变体 ETag、NUL 和穿越；检验正文与头，不只检验状态码。
- 发布在临时 Git 仓库和测试服务演练。故障注入覆盖拉取失败、脏发布源、生成失败、校验失败、指针切换失败、切换后探测失败和并发发布；同时连续请求页面，证明旧产物保留且服务无空窗。开发工作树脏状态不应阻塞独立发布 checkout。
- 浏览器固定视口 390/768/1280，抽样首页、两版同名工具页、长参数页、目录、缺失页，两种主题及实际存在的语言。验证搜索精确匹配、键盘 Tab/Enter、skip link、焦点、表格和打印；截图用于佐证，不以像素完全相等作为唯一断言。
- UI 字面量译文用人工核对与内容约束结合，不以“含 CJK 字符”直接判英文页错误。Revit 实机对话框行为未复测时明确记录为代码核对，不伪报真机通过。
- 合并门禁加入以上静态与行为检查。隔离环境全绿后再按项目正常部署流程发布；线上复测首页、精确搜索、深链接、404、语言切换及清单。全部必做包通过才完成规格；体验延期项单列，不静默消失。

## Out of Scope

- 执行 #27 的上游 rebase、改变 tool/inputSchema、add-in 业务实现、产品写权限与默认行为。
- 恢复 ADR-0007 已放弃的全面翻译；为没有维护者的上游正文新增译文。
- 更换 MkDocs/Material、全站视觉重做、引入外部搜索服务。
- 编造缺失实验记录、将历史数字升级为性能承诺，或把本轮代码核对等同 Revit 实机验证。
- 强制 PWA manifest/security.txt、全局禁止跨语言相同标题。搜索自动补全与进一步分包优化留作有测量证据的后续工作。
- 本轮直接修改线上服务、运行发布、提交或推送代码。本规格的完成条件针对后续实施。

## Further Notes

### 对原 review 的校准

1. 原报告分级总数、表格与正文条目数不一致；以 W1–W9 和验收项作为追踪单位，不沿用“40 条”或 P0 总数。
2. 版本契约混淆是优先修复项，但两个版本各自的 schema 正确；整改目标是身份与适用性，不是让两套参数强行相等。
3. 原发布脚本已有第二次 rename 失败后的回退。缺口是切换空窗、成功后旧版清理过快、来源与结果可观测性，不是完全没有回退。
4. “所有农场必然卡死”未获真机证明；当前正文已建议独立模型副本。环境变量缺文档属实，应说明场景而非要求所有会话启用。
5. 性能中文页已承认原始记录缺失；修复错误全文链接与证据表达，不删除已有有用摘要，也不补造原始日志。
6. HEAD/GET 必须在相同请求头下比较；304 不逐字复制所有 200 头。缓存验收依据表示语义。
7. 相对 hreflang 需改为符合搜索引擎要求的绝对地址；LAN 站搜索引擎影响有限，但公开构建同样受益。
8. 移动端横滚本身不是失败；本规格约束主要说明可读且所有字段可访问。无引用 GIF 是产物体积问题，不是已证实的首屏下载问题。
